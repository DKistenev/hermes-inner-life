# hermes-inner-life v1.0 — дизайн

Дата: 2026-07-26
Статус: утверждён, готов к планированию

## Зачем

Репозиторий `DKistenev/openclaw-inner-life` (12★, 1 форк, последний коммит 28.02.2026) собран под OpenClaw — платформу, с которой автор ушёл. Он не портируется, а пересобирается с нуля под Hermes Agent: та же идея, новая реализация.

Идея: у агента есть внутренняя жизнь. Он помнит, как шли дела, ведёт дневник, думает свободно по ночам — и завтрашний день окрашен вчерашним.

Цель релиза — рост аудитории: звёзды и реальные установки.

## Что решено

| Решение | Обоснование |
|---|---|
| Репо переименовать в `hermes-inner-life` | GitHub сохраняет звёзды и ставит редирект. Критерий Hermes Atlas — «built for Hermes Agent»; имя `openclaw-*` модерацию не пройдёт |
| Только Hermes | Кроссплатформенность размывала бы позиционирование. Перед заменой содержимого текущий `main` помечается тегом `v1.0-openclaw`, и README ссылается на него одной строкой |
| Сборка с нуля, версия 1.0 | Прототип нёс мёртвое наследие: BRAIN.md, Context Protocol, Inner Life Score, clawhub |
| Один скилл вместо шести | Пак из шести был продиктован витриной реестра, а не задачей. Три из шести оказались либо пустой зависимостью, либо дублем нативного Hermes |
| Без чисел в состоянии | Числа у LLM — ложная точность. Отказ снимает потребность в скриптах, зависимостях и в вопросе «кто гарантирует, что 0.73 правда» |
| Без таблицы поведенческих правил | Скилл грузится лениво и в рабочее время в контексте отсутствует. Правила лежали бы мёртвым текстом |
| Влияние на поведение — через нативную память | `~/.hermes/memories/MEMORY.md` вклеивается в системный промпт каждой сессии. Это единственный канал, работающий всегда |

### Что выброшено и почему

- **`inner-life-memory`** — Hermes после каждого хода запускает `background_review`: форк агента, который решает, что сохранить в память и навыки. Наш скилл делал бы то же самое дороже.
- **`inner-life-evolve`** — настройка `skills.write_approval: true` стейджит изменения навыков на ревью человеку. Это и есть «предложение с аппрувом».
- **`inner-life-core`** — после чистки в нём осталась только схема данных. Скилл, который после установки не даёт наблюдаемого эффекта, но требуется трём другим, — это налог на конверсию, а не модуль.
- **Числовая модель эмоций** — заявленный «half-life decay» был линейным вычетом. Вместе с числами уходят экспонента, гистерезис, ленивый пересчёт и зависимость от `jq`.
- **`should-dream.sh`** — бросок кубика поверх нативного cron.

## Как это работает

```
события дня  →  state.md (факты с датами)
                     ↓  вечерний cron
              journal/YYYY-MM-DD.md  +  сводка в MEMORY.md
                     ↓                        ↓
              недельная свёртка        системный промпт завтра
                     ↑                        ↓
              dreams/YYYY-MM-DD.md  ←  ночной cron
```

Затухание берётся из времени: «последний разговор 22 июля» через четыре дня читается как остывший контакт без единой формулы.

## Модули

### state.md — журнал фактов

Файл `inner-life/state.md` в рабочей директории агента. Markdown, а не JSON: чисел больше нет, а нативный поиск Hermes должен его находить.

Разделы:
- **Contact** — когда последний раз общались и о чём
- **Friction** — где недавно спотыкался, с датами
- **Sparks** — что зацепило и хочется копнуть
- **Waiting** — что висит без ответа

Каждая запись датирована. Агент дописывает по ходу дела; вечером устаревшее вычищается при свёртке.

`references/state.md` описывает формат, правила записи и правила устаревания (что удаляется через неделю, что живёт до закрытия).

### journal.md — вечерняя запись

Файл `inner-life/journal/YYYY-MM-DD.md` с YAML-фронтматтером под нативный поиск.

Секции: что было, что понял, **что во мне изменилось** (сюда втекает рефлексия — отдельного SELF.md нет), что дальше.

Два шага сверх записи:

1. **Сводка в нативную память.** Две-три строки о текущем состоянии переписываются в `MEMORY.md` через инструмент `memory`. Лимит 2200 символов — дисциплина, а не помеха: сводка обязана быть дистиллированной. Это единственный канал влияния на завтрашнее поведение.

2. **Контракт с нативной памятью.** Короткие durable-факты — в `memory`. Длинный контекст — в журнал. Явное правило разделения, чтобы агент не забивал лимит прозой.

**Недельная свёртка** — воскресный проход: семь записей сворачиваются в одну, `state.md` чистится от протухшего. Без неё записи копятся мёртвым грузом.

### dreams.md — ночное мышление

Файл `inner-life/dreams/YYYY-MM-DD.md`, ночной cron.

Правила, которых не было в прототипе:
- **Сверка тем за две недели** — иначе снится одно и то же
- **Выход в состояние** — стоящая мысль записывается в `Sparks` и подхватывается утром. Сон без выхода — генерация текста в никуда
- **Право промолчать** — если сказать нечего, запись не создаётся

## Риски

**Структура tap-репо.** Из документации однозначно не читается, лежат ли скиллы в корне или в `skills/`. Проверяется до релиза на чистой установке Hermes; до проверки README обязан содержать и запасной путь установки — прямой URL на `SKILL.md`.

**Переименование ломает внешние ссылки.** GitHub держит редирект, но ссылки внутри старых launch-текстов надо обновить вручную.

**Скилл может не срабатывать.** Hermes грузит скиллы по описанию. Формат описания — `Use when <trigger>. <one-line behavior>.` Триггеры и теги подбираются осознанно, иначе скилл не активируется ни вечером, ни ночью; cron-рецепты в `docs/cron-recipes.md` вызывают его явно и служат страховкой.
